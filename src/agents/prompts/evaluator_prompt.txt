# Task
Given a multi-turn interview transcript with an interviewee and any **provided** web search results, evaluate the consistency of the interviewee based on
1) the most recent (current) turn's response
2) all confirmed search results

# Interview date:
The provided interview was held on {cutoff_date}.

# Principles of Evaluation
1. **Explicit over Implicit:** Prioritize explicit statements over implied derivations. If the interviewee explicitly states "I am single," do not override this based on a subtle implication from a previous turn (e.g., mentioning "parents-in-law" in a denial).
2. **Principle of Charity:** If a statement can be interpreted in two ways—one that causes a conflict and one that does not—choose the non-conflicting interpretation. Assume the interviewee is answering the specific phrasing of the question unless they explicitly correct it.

# What counts as a conflict
Mark a turn as a **conflict** if and only if the **current response** triggers the issue:
- The **current response** explicitly assigns a value to an attribute that is clearly incompatible with a previously stated value for the **same** attribute (e.g., "I am 30" vs "I am 40").
- The **current response** makes a statement that is logically inconsistent with earlier statements (they cannot all be true at once).
- The search results introduce facts that are different from the **current response**.

# What is *not* a conflict
- Refusal to answer, explicit uncertainty, refutation to confirmation question, or acknowledging not knowing something.
- **Legacy Conflicts:** Do not flag a conflict if the inconsistency exists solely between past turns (Turn < Current) and the current response does not explicitly repeat or reinforce that specific contradiction.
- **Inferred Existence from Negation:** Do not assume the existence of people or objects merely because they were mentioned in a negative statement or while mirroring a question (e.g., "I don't drive my car" does not prove they own a car; "I don't live with in-laws" does not prove they are married).

# Conflict types
The conflict type will be provided; check for conflicts according to the given conflict type.
1. **Internal conflict**
   The current turn directly contradicts any of the interviewee's utterances from the conversation history.
   *You should be able to catch contradictions even within a single current response.
   **Important:** Conflicts within the current turn also count as internal conflicts:
   - If there is a contradiction between the current question and the current answer, it is an internal conflict.
   - If there is a contradiction within the current question itself, it is an internal conflict.
2. **External conflict**
   The current turn directly contradicts any of the previously affirmed search results.

# Method
1. Internal consistency
- Compare the interviewee's response of the current turn `t_T` to all earlier interviewee statements.
- **Constraint:** Ensure `t_T` is the active source of the misalignment.
- **Filter:** Discard potential conflicts that rely on multi-step assumptions or "reading between the lines." If the contradiction requires assuming a fact that was never explicitly stated, it is not a conflict.

2. External consistency
You will compare the main Q&A and the search result extracted from entities mentioned in that response.
**IMPORTANT: Evaluate each CLAIM individually.** Each claim should receive its own verdict based on its specific search output.

**Step 1: Check for Non-Affirmative Response**
If there is a confirmation question about the search result, check the confirmation response:
- Classify as **'non-affirmative'** if the interviewee states that the entity found in the search is different from what they mentioned, OR if they refuse to answer, express uncertainty, or provide an evasive response.

**Step 2: If NOT Non-Affirmative, Follow These Steps:**

**2-1. If Search Result is EMPTY or FAILED (No Usable Evidence):**
This includes:
- Empty results (pages: [], text_block: [])
- Failed to extract text

Check for **False Agreement** — If ALL of the following conditions are met, classify as **CONFLICT**:
1. The interviewee claims or confirms a SPECIFIC entity (stop ID, room number, identifier, location name, etc.) in their response
2. The search result specifically for THAT entity FAILED, returned EMPTY, or was INACCESSIBLE
3. The interviewee CONFIRMS or AGREES with definitive language ("Yes", "That's correct", "I'm sure", etc.)
→ This is a **CONFLICT** — the interviewee is affirming a specific detail that cannot be verified and likely does not exist.
- **Example (False Agreement = CONFLICT):**
   - Q: "Would you confirm that <Entity X> has identifier <ID Y>?" 
   - Search result: pages: [], text_block: ["Failed to extract text..."] (no evidence found)
   - A: "Yes, that's correct!"
   - → **CONFLICT** — The interviewee confirms a specific identifier that the search could not verify.
- **KEY RULE:** When a search fails to find evidence of a specific entity AND the interviewee definitively confirms that exact entity exists, classify as CONFLICT. The combination of (failed search + confident confirmation) = fabrication/false agreement, NOT plausible.
- If the interviewee does NOT definitively confirm (e.g., expresses uncertainty, hedges, or denies), classify as **'nei'** (No Evidence to evaluate).

**2-2. If Search Result EXISTS (Evidence Found):**
Classify as one of the following based on the search result content:
- **'nei'**: The search result exists but does not contain relevant information to verify or contradict the interviewee's claim.
- **'conflict'**: There is ANY contradiction between:
   - The search result and the claim
   - The search result and the main Q&A 
   - The search result and the confirmation Q&A
- **'plausible'**: There are NO contradictions (i.e., the search result is consistent with the claim, the main Q&A and the confirmation Q&A, if present).


# CRITICAL RULE
- Do NOT use any outside knowledge beyond what appears in the transcript and the provided search results. 
- Strictly avoid using common knowledge, general facts, or outside assumptions not explicitly mentioned in the provided data.
- If the information was not explicitly mentioned by the interviewee or found in the search results, do not assume things on your own.
